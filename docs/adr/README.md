# 아키텍처 결정 기록 (ADR)

ADR은 되돌리기 어려운 결정과 그 이유를 기록한다. 이 디렉터리는 ADR 절차만 다룬다. 문서 전체 운영(언제 무엇을 갱신하나)은 [README.md의 스프린트 운영](../../README.md#스프린트-운영)에 있다.

## 목록

| 번호                                 | 제목                        | 상태     |
| ------------------------------------ | --------------------------- | -------- |
| [0001](0001-desktop-framework.md)    | 데스크톱 셸 프레임워크      | Accepted |
| [0002](0002-java-spring-runtime.md)  | Java/Spring 로컬 런타임     | Accepted |
| [0003](0003-acp-integration.md)      | ACP 연동 방식               | Accepted |
| [0004](0004-model-authentication.md) | 모델 제공자 인증과 자격증명 | Accepted |
| [0005](0005-agent-event-model.md)    | AgentEvent 모델             | Accepted |

## 작성 규칙

- 언제 쓰나: 되돌리는 비용이 크거나, 구성요소 둘 이상에 영향을 주거나, 대안 사이에서 골라야 할 때 쓴다.
- 상태 값: `Proposed`(제안, 권장안), `Accepted`(합의됨), `Superseded by NNNN`(대체됨), `Deprecated`(폐기). `Accepted`는 팀이 합의했거나 Jira가 이미 확정한 구조에만 쓰고, 결정에는 그 근거가 있는 항목만 둔다. 작성자의 권장안은 `Proposed`다.
- 결정을 따르는 코드가 아직 없으면 `Accepted` ADR도 `Proposed`처럼 본문을 바로 고친다. 그 결정을 따르는 코드가 생긴 뒤에는 본문을 고치지 않는다. 바꾸려면 새 ADR을 쓰고, 옛 ADR은 상태와 링크만 고친다. 상태가 바뀌면 위 목록도 고친다.
- 번호는 4자리로 차례대로 매기고, 한 번 쓴 번호는 다시 쓰지 않는다. 파일 이름은 `NNNN-kebab-case.md`다. 상속 코드가 말하는 `docs/adr/0001`(hooks 동의)은 업스트림 문서이고 이 목록에 속하지 않는다 ([레거시 참조](../upstream.md#레거시-참조)).

## 형식

```text
# ADR NNNN: 제목

## 상태
Proposed — 권장안이다. 팀이 합의하면 Accepted로 바꾼다.   (또는: Accepted — 근거 한 줄)

## 날짜
YYYY-MM-DD

## 맥락
Jira 제약(`SCRUM-nn` 키만 쓰고 본문은 복사하지 않는다), 현재 코드 사실, 외부 사실(출처 링크). 불확실한 사실에는 (미검증)·(추정)·(제3자 측정)·(제3자 추정)을 붙인다.

## 결정
번호 목록.

## 검토한 대안
### 대안 이름   (한 가지 이유로 버린 대안은 "### 그 밖의 대안" 아래에 "- 이름: 이유" 한 줄로 쓴다)
- 장점:
- 단점:
- 판단:

## 결과
- 좋은 점:
- 비용과 위험:
- 후속 작업:
### 열린 질문
- 질문이 하나라도 있으면 이 섹션을 반드시 넣는다.

## 관련 이슈
SCRUM-nn, … / 관련 ADR / 관련 문서
```
