# 업스트림 (pixel-agents)

agents-room이 [pixel-agents](https://github.com/pixel-agents-hq/pixel-agents)에서 무엇을 가져왔고, 무엇을 버리며, 업스트림을 어떻게 따라가는지 기록한다. 상속 코드 상세의 단일 출처다.
목표 설계는 [architecture.md](architecture.md), 라이선스 본문은 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)에 있다.

목록에 없는 파일은 그 영역의 기본 판정을 따른다: `server/`와 `adapters/vscode/`는 버리고, `e2e/`는 고쳐 쓰고, 나머지 영역은 그대로 쓴다.

- `core/`: `provider.ts`는 AgentEvent의 출발점으로 고쳐 쓴다.
- `server/`: Java로 다시 구현한다 ([ADR 0002](adr/0002-java-spring-runtime.md)). "개념만 옮긴다"는 TS 코드 대신 구조만 가져온다는 뜻이다: 단일 상태 저장소 (broadcast에는 타입 검사를 더한다), `kind`로만 하는 dispatch, `sessionId` → `agentId` 대응, 연결 시 스냅샷, tmp+rename 저장. 버리는 hooks·JSONL·휴리스틱 타이머의 역할은 ACP client가 대신한다. `assetLoader.ts`는 옮기지 않는다. 데스크톱 렌더러가 번들 에셋을 스스로 읽기 때문이다 (`webview-ui/src/localAssets.ts`).
- `adapters/vscode/`: 역할은 데스크톱 셸(`PixelAgentsViewProvider`)과 Process supervisor(`agentManager`)로 간다.
- `webview-ui/`: `transport/index.ts`와 `runtime.ts`에 데스크톱 분기를 더했다. 데스크톱 분기(`transport/desktopTransport.ts`)는 런타임 소켓을 계약의 agents-room 프레임으로 타입 짓고, 상속 UI가 보내는 업스트림 명령(`webviewReady` 포함)을 런타임에 보내지 않는다. 런타임이 보낸 프레임은 `runtimeState.ts`가 담는다. 런타임 명령은 `transport/index.ts`의 `sendRuntimeCommand`로 런타임 소켓에 보낸다. `WebSocketTransport`는 받고 보내는 프레임의 타입을 인자로 받고, 첫 구독자 전에 온 메시지를 잡아 두고(`transport/heldMessages.ts`), 접속 주소를 연결할 때마다 다시 묻는다. 에셋 로딩은 `browserMock.ts`에서 `localAssets.ts`로 옮겼고, Vite 빌드가 디코딩한 JSON을 함께 내보낸다. `BottomToolbar`는 데스크톱에서 "Layout"과 "+ Agent"를 숨긴다. `browserMock.ts`는 mock ACP 이벤트를 내게 고친다(아직 하지 않았다). `DebugView.tsx`는 JSONL 전용이다.
  - 데스크톱의 화면과 에이전트 처리는 상속 코드를 다시 쓰지 않고 새 폴더 `desktopUi/`에 두었다 ([architecture.md](architecture.md#데스크톱-렌더러-화면)). `App.tsx`는 데스크톱에서만 픽셀 월드를 세 열 화면(`DesktopShell`)에 넣는다. 그래서 `useExtensionMessages.ts`는 VS Code·standalone의 메시지와 데스크톱의 에셋 프레임만 다루고, AgentEvent 처리로 다시 쓰지 않았다. 업스트림 프레임이 계약에서 빠질 때(`server/`, `adapters/vscode/`를 지울 때) 이 파일도 다시 본다.
  - `toolUtils.ts`는 고치지 않았다. 데스크톱은 `setProviderCapabilities`로 읽기 Tool 목록을 ACP kind(`read`, `search`, `fetch`)로 두고 kind를 엔진의 Tool 이름으로 넘긴다. `STATUS_TO_TOOL`의 영어 접두어 해석은 VS Code와 standalone만 쓴다. 데스크톱 캐릭터의 라벨은 `desktopUi/AgentLabels.tsx`가 그리고, `ToolOverlay.tsx`는 말풍선 타입이 늘어난 것만 따라갔다.
  - 엔진은 작게 고쳤다 (critique C6): `characters.ts`에 자리에 앉은 채 멈추는 `pinnedToSeat`, `officeState.ts`에 그 setter와 반투명(`isOffline`), Tool kind 아이콘(`activityIcon`), 시간이 지나면 사라지는 말풍선과 사라지지 않는 말풍선, 런타임 에이전트의 권한·오류 말풍선을 클릭으로 지우지 않는 규칙(R9), `renderer.ts`에 반투명과 새 말풍선·아이콘 그리기, `office/types.ts`와 `office/sprites/spriteData.ts`에 그 타입과 스프라이트 6개(`bubble-error`, `bubble-cancelled`, `bubble-warning`, `icon-search`, `icon-terminal`, `icon-generic`)를 더했다. 이 필드는 데스크톱만 켜므로 VS Code와 standalone의 동작은 그대로다. `index.css`에는 `--font-pixel`의 한글 대체 글꼴과, 데스크톱 패널(`.desktop-type`)만 쓰는 글꼴 한 쌍(크기를 맞춘 FS Pixel Sans와 한글 글꼴, `size-adjust`)과 단어 단위 줄바꿈(`word-break: keep-all`)을 더했다. VS Code와 standalone은 그대로 `FS Pixel Sans`를 쓴다 ([ux.md](ux.md#상속한-시각-요소)).
  - `testHooks.ts`에는 캐릭터의 상태, 데스크톱의 런타임 캐릭터와 선택, 캐릭터의 화면 위치를 읽는 hook을 더했다. Intro 파일 3개(hooks 동의 단계를 빼고 온보딩으로 바꾼다)는 아직 고치지 않았다. 투어가 hooks 동의 요청으로만 열리므로 데스크톱에서는 열리지 않는다.
- `e2e/`: 프로세스 경계에서 mock하는 원칙을 유지하고, mock 대상을 stdio JSON-RPC로 말하는 mock ACP agent로 바꾼다. 셸이 Electron이므로 `helpers/launch.ts`의 `_electron.launch` 코드를 옮겨 쓴다 ([ADR 0001](adr/0001-desktop-framework.md)). `helpers/allure-labels.ts`에는 데스크톱 영역(`desktop-shell`, `desktop-runtime`, `desktop-agent`, `desktop-ui`)을 더했다.
- `.github/`: 배포 워크플로 2개(`publish-extension.yml`, `update-badges.yml`)와 `dependabot.yml`을 지웠다 ([남은 업스트림 흔적](#남은-업스트림-흔적)). `ci.yml`에서는 npm 패키지 검사, 상속한 e2e 행렬(VS Code와 standalone, 3 OS × 3 shard), Vercel 미리보기 배포를 지웠다. 남은 것은 ubuntu 품질 검사 job과 `required-checks`이다. 로컬 런타임(`runtime/`)을 Windows와 ubuntu에서 빌드하고 테스트하는 `runtime` job과, 데스크톱 셸의 단위 테스트와 Electron e2e(`npm run e2e:desktop`, 가짜 런타임과 실제 런타임 jar)를 Windows에서 돌리는 `desktop-windows` job을 더했다. AsyncAPI 명세 검증, `messages.ts` drift check, 계약 fixture 검사(`npm run contract:check`), `e2e/README.md` 테스트 목록 drift check 중 하나라도 실패하거나 `runtime`이나 `desktop-windows` job이 실패하면 CI 실행이 실패한다 (`CI`·`Runtime`·`Desktop` job과 `Required Checks`). main에는 branch protection이 없어서 병합은 막히지 않는다. Markdown만 바꾼 PR에서는 CI가 돌지 않는다. 테스트 목록이 든 `e2e/README.md`만 예외다. 상속한 e2e는 CI에서 돌지 않고 로컬 `npm run e2e`로만 돈다. 그래서 `e2e/README.md`의 "CI green on this suite is the safety net" 문장은 맞지 않는다. 버릴 스크립트(`npm-package-contract*.mjs`, `verify-npm-package.mjs`, `assemble-vercel-output.mjs`)와 `vercel.json`은 CI가 더는 부르지 않지만 파일은 남아 있다.
- 그 밖: `generate-messages.ts`에는 Java 대상을 더하고, TS 바인딩에 상속 프레임을 뺀 union(`RuntimeServerMessage`, `RuntimeClientMessage`)을 선언하게 했다. `CLAUDE.md`를 agents-room 기준으로 다시 쓰는 것은 별도 작업이다. `icon.png`는 새 아이콘으로 바꾼다.

## 업스트림 동기화

- 기본은 cherry-pick이다 (제안). 업스트림 main을 통째로 병합하지 않는다. `server/`와 `adapters/`를 바꿔 나가면 충돌이 커지기 때문이다.
- 새 커밋은 아래처럼 확인한다.

```bash
git remote add upstream https://github.com/pixel-agents-hq/pixel-agents.git   # 처음 한 번만
git fetch upstream
git log --oneline d1e007a..upstream/main
```

- 기준 커밋 뒤의 업스트림 커밋 (2026-10-20 기준): 검토 후보는 `8aa7794` (#426, 에디터 alt-drag 복제, desk riders, stroke undo, 색 복사)와 `4d72e6d` (#404, 모바일 web-app 셸, 터치 입력, 에이전트 카드)다. `afed339` (#347, standalone 내장 터미널), `52ad24a` (#405, 디렉터리 실행 화면), `b1bafd0` (#434, v1.5.0 릴리스)는 VS Code나 standalone 전용이거나 릴리스 커밋이라 우선순위가 낮다.
- 반영하면 [CHANGELOG.md](../CHANGELOG.md)에 해시와 업스트림 PR 번호를 적는다.
- 상속 코드 주석 속 업스트림 문서 이름은 고치지 않는다. 병합을 깨끗하게 하기 위해서다 → [레거시 참조](#레거시-참조).

| `docs/adr/0001`                   | `CLAUDE.md`, `server/src/providers/hook/consentGate.ts`              | [업스트림 ADR 0001 (hooks 동의)](https://github.com/pixel-agents-hq/pixel-agents/blob/d1e007a9fdf3003c252d2973abe1999ae59aec33/docs/adr/0001-consent-choices-send-immediately-and-revise-as-absolute-state.md). agents-room의 [ADR 0001](adr/0001-desktop-framework.md)이 아니다 |

## 알려진 불일치

포크 기준에서 문서나 설정이 코드와 다르게 적힌 곳이다. 코드를 기준으로 한다.

| 항목                       | 코드 (포크 기준)                                                                                                                                        | 다르게 적힌 곳                                                                                                        |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 메시지 수                  | `core/asyncapi.yaml`에 ServerMessage 31개, ClientMessage 22개                                                                                           | CLAUDE.md: 27개, 18개                                                                                                 |
| WebSocket 재연결 지연      | 1초부터 두 배씩 늘려 30초에서 멈춘다 (`webSocketTransport.ts`)                                                                                          | CLAUDE.md: 250ms부터 4s까지                                                                                           |
| `package.json` `files`     | `CHANGELOG.md`, `LICENSE`, `dist/extension.js`, `dist/uninstall.js`를 포함하고 `core/asyncapi.yaml`은 포함하지 않는다                                   | CLAUDE.md: `core/asyncapi.yaml` 포함, `dist/extension.js` 제외                                                        |
| 폰트 경로                  | `webview-ui/public/fonts/`                                                                                                                              | CLAUDE.md: `webview-ui/src/fonts/`                                                                                    |
| CSS 토큰 이름              | `--color-*`, `--shadow-pixel`, `--font-pixel` (`webview-ui/src/index.css`)                                                                              | CLAUDE.md: `--pixel-*`                                                                                                |
| ESLint `pixel-shadow` 규칙 | 토큰은 `--shadow-pixel`뿐이다. 그래서 `var(--shadow-pixel)`만 쓴 인라인 `boxShadow`도 이 규칙에 걸린다                                                  | `eslint-rules/pixel-agents-rules.mjs`: 없는 토큰 `var(--pixel-shadow)`를 허용하고, 메시지는 `--pixel-*` 토큰을 권한다 |
| `server/__tests__`         | 29개 파일                                                                                                                                               | CLAUDE.md: 28개                                                                                                       |
| `npm run import-tileset`   | `scripts/import-tileset-cli.ts`가 없어 실행되지 않는다. 0~5단계 tileset 스크립트도 없다                                                                 | `package.json` 스크립트, CLAUDE.md의 7단계 파이프라인                                                                 |
| CLI 기본 포트              | OS가 고르는 임시 포트 (`server/src/cli.ts`)                                                                                                             | `core/asyncapi.yaml` `servers.local`: 3100                                                                            |

| Tool 이름 분기             | `server/src/hookEventHandler.ts`가 `toolName !== 'Task' && toolName !== 'Agent'`로 Claude Tool 이름을 비교한다                                          | CLAUDE.md: 런타임은 `kind`로만 dispatch한다                                                                           |
| 바닥 타일                  | `floor_0`~`floor_8` 개별 PNG (`webview-ui/public/assets/floors/`)                                                                                       | CLAUDE.md: `floors.png` 한 장에 7패턴                                                                                 |
