# UX 설계

이 문서는 렌더러(Renderer)가 무엇을 어떻게 보여주는지 정한다: 화면, 상태와 행동의 시각 표현, UI 문구, "관찰한 것만 보여준다" 규칙. MVP 화면만 다룬다. 용어는 [architecture.md#용어집](architecture.md#용어집), 상태 전이와 이벤트는 [ADR 0005](adr/0005-agent-event-model.md), 인증 정보 표시 규칙은 [ADR 0004](adr/0004-model-authentication.md)에 있다.
데스크톱 렌더러에 Sprint 0 화면이 있다: 3열 메인 화면, 프로젝트·에이전트 패널, Detail Panel, 캐릭터 행동, 권한 요청에 답하는 최소 버튼이다([Sprint 0 구현](#sprint-0-구현)). 에이전트 추가와 설정, 권한 요청 대화상자, "중지", 진단 화면은 아직 없다. 데스크톱 셸의 런타임 실패 대화상자도 있다([문구 목록](#문구-목록)). 괄호 안의 SCRUM 키는 그 동작의 근거인 Jira 이슈다. 문구는 [문구 목록](#문구-목록)의 근거 열에 SCRUM 키가 있는 것만 Jira 원문이고, 나머지 배치와 문구는 모두 MVP 첫 구현을 위한 제안이다.

## 화면 구성

### 시작 상태

- 별도 시작 창 없이 메인 화면을 "프로젝트 없음" 상태로 연다. 픽셀 월드는 기본 사무실을, 왼쪽 패널은 최근 프로젝트와 "프로젝트 열기"를 보여준다. SCRUM-18이 요구하는 픽셀 월드, 프로젝트 선택 상태, 에이전트 패널이 한 화면에 모인다.
- 폴더 선택을 취소하면 화면을 그대로 둔다. 접근할 수 없는 폴더를 고르면 오류를 보여주고 다시 고르게 한다. 옮겨지거나 지워진 프로젝트에는 "위치 다시 지정"을 보여준다 (SCRUM-18, 31, 32). 흐름은 [architecture.md#주요-흐름](architecture.md#주요-흐름)에 있다.
- 실행기(Harness)가 설치되어 있지 않아도 앱은 열린다. 해당 에이전트 카드에 "에이전트 실행기 설치/연결 필요"를 보여준다 (SCRUM-36).
- 설정 파일이 손상되었으면 그 사실을 알리고 "초기화 유지"와 "복구 시도" 중에서 고르게 한다. 처리 방식은 [architecture.md#persistence](architecture.md#persistence)에 있다 (SCRUM-37).

### 메인 화면

| 영역                         | 내용                                                                                                                                                                        |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 왼쪽: 프로젝트·에이전트 패널 | 프로젝트 이름과 실제 경로, 최소 파일 트리, 에이전트 카드 목록(이름, 실행기 배지, 설정 상태, 에이전트 상태, "에이전트 시작"/"에이전트 종료"), "에이전트 추가" (SCRUM-18, 31) |
| 가운데: 픽셀 월드            | 사무실, 캐릭터(Character), 말풍선. 캐릭터를 클릭하면 선택되고 카메라가 따라간다 (상속한 동작; SCRUM-27, 28)                                                                 |
| 오른쪽: Detail Panel         | 선택한 캐릭터의 패널이다. 프로젝트를 열면 첫 에이전트를 선택해 바로 연다. 에이전트가 실행 중이어도 창 크기 조절과 패널 조작이 막히지 않는다 (SCRUM-19, 22, 31)              |

Detail Panel은 위에서 아래로 다음 순서다.

1. 헤더: "Agent명", 실행기 배지(이름과 같으면 뺀다, [에이전트 이름 식별](#여러-에이전트-구분)), 설정 상태, 에이전트 상태.
2. 연결 정보: 모델 제공자(Model Provider), 모델("실행기 기본값" 또는 "어댑터 보고" 값), 인증 표시값(R11), "작업 폴더 설정", "실제 OS/Harness 강제 제한 여부".
3. 현재 실행: "작업 요청", "현재 Tool"(제목과 행동), "세션 상태"(값은 [상태 어휘](#상태-어휘)의 세션 상태 표).
4. "최근 이벤트": 수신 순서대로 보여준다 (예: 파일 읽기 → 테스트 실행 → 결과 보고). Tool 호출(Tool call) 상태 변화, 권한 요청(Permission request)과 응답, 메시지 요약을 담는다. 생각 청크(`agentThoughtChunk`)는 접힌 상태로 "에이전트가 보고한 생각"이라고 표시하고 저장하지 않는다. 실행 이력(SCRUM-16, 52)이 모델의 내부 추론을 저장 범위에서 뺐기 때문이다.
5. Plan, 최종 응답과 실행 결과, 컨텍스트 사용량. Plan과 사용량은 보고된 경우에만 보인다 (R2, R12).
6. 작업 입력창과 "중지". 입력은 선택한 에이전트에만 보낸다. 받는 에이전트가 늘 화면에 보이게 하려는 것이다 (SCRUM-31). "중지"는 실행(Run)이 진행 중일 때(`running`, `awaiting_permission`)만 보이고 그 실행만 취소한다 (SCRUM-24). 카드의 "에이전트 종료"는 프로세스를 끝내며, 실행 중이면 런타임이 실행을 먼저 취소한다 ([ADR 0005](adr/0005-agent-event-model.md)).

### 에이전트 추가와 설정

- 순서: "에이전트 추가" → 실행기 → 모델 제공자(MVP의 Bedrock은 "Amazon Bedrock (mock)"이고, 실제 AWS의 region과 profile 선택은 post-MVP다. SCRUM-25·34, [ADR 0004](adr/0004-model-authentication.md) 결정 10) → 호환 모델 → 인증 방식(Auth method) → "연결 확인" → 이름 → 저장 (SCRUM-10, 25). 저장 결과는 카드의 설정 상태로 보여준다 ([상태 어휘](#상태-어휘)).
- 실행기가 달라도 같은 화면과 절차를 쓴다 (SCRUM-26, 66). 실행기를 바꾸면 제공자, 모델, 인증 선택지를 다시 계산하고, 실행기가 실제로 지원하는 것만 보여준다. 호환 규칙은 [architecture.md#agent-config-registry](architecture.md#agent-config-registry)에 있다. 검증되지 않은 모델은 고를 수 없게 하거나 "실험적"으로 표시한다 (SCRUM-25).
- Codex의 인증 선택지는 어댑터가 보고한 `authMethods`에서 오고, 기본은 ChatGPT 로그인이다(MVP 확인용). API key 입력을 필수 절차로 만들지 않는다 (SCRUM-65). Claude Code는 인증 선택지가 없고 "Amazon Bedrock (mock)"으로만 연결한다 (SCRUM-67). 실행기 이름은 어댑터가 `initialize`에서 보고한 `agentInfo.title`을 쓴다 (claude-agent-acp는 "Claude Agent"). Anthropic은 Agent SDK를 쓰는 제품이 Claude를 가리킬 때 "Claude Code"나 "Claude Code Agent"가 아니라 "Claude Agent" 같은 이름을 쓰라고 하고, 설명 문장에서 "Claude Code를 실행한다"고 쓰는 것은 허용한다 ([branding](https://code.claude.com/docs/en/agent-sdk/overview#branding-guidelines), [Legal](https://code.claude.com/docs/en/legal-and-compliance)) (제안). 어떤 선택지를 보여줄지는 [ADR 0004](adr/0004-model-authentication.md)를 따른다.
- "연결 확인"이 무엇을 검사하는지는 [ADR 0004](adr/0004-model-authentication.md)에 있다. 결과는 단계별로 나눠 보여주고, 검사할 수 없는 단계는 "검사 불가"로 쓴다 (SCRUM-49).
- 실행 전에 작업 폴더와 실제 강제 제한 여부를 따로 보여준다 (R10). 위험할 수 있는 설정은 기본으로 꺼 둔다 (SCRUM-35).

### 권한 요청 대화상자

- 필드: "요청 에이전트"(이름, 캐릭터 강조), "실제 명령 또는 대상"(Tool 제목, 보고된 `rawInput`과 위치를 마스킹한 뒤 표시), "작업 디렉터리"(세션 `cwd`), "승인 선택지" (SCRUM-33).
- 선택지는 어댑터가 보낸 `options`만 보여주고, 라벨은 kind로 정한다: `allow_once` "이번만 허용", `reject_once` "거부", `allow_always` "항상 허용", `reject_always` "항상 거부". "항상" 선택지도 MVP에 넣는다. 그 결정을 기억하고 적용하는 것은 어댑터이며 agents-room은 저장하지 않는다. 렌더러는 사용자가 고른 선택지만 보낸다.
- 어댑터가 보낸 권한 요청은 모두 보여주고, 자동으로 허용하는 것은 없다 (SCRUM-15, 33). 대화상자를 닫아도 허용한 것으로 보지 않는다. 요청은 대기 상태로 남고 캐릭터의 "..." 말풍선도 유지된다. 말풍선이나 Detail Panel에서 대화상자를 다시 열 수 있다. 요청 정보가 불분명하면 "요청 정보가 불분명합니다"를 표시한다. 실행을 취소하거나 에이전트를 종료하면 대기 중인 요청은 런타임이 취소하고 대화상자도 닫힌다. 어댑터가 요청을 거두어도(`permissionResolved {outcome: cancelled}`) 대화상자는 닫힌다.
- 요청마다 요청한 에이전트를 표시하고, 여러 에이전트의 요청을 섞지 않는다. 같은 에이전트의 요청은 차례로 보여준다 (SCRUM-66).
- 대화상자는 SCRUM-33(Sprint 2)에서 만든다. 그 전까지는 Detail Panel에 같은 필드와 선택지 버튼만 둔다 (D16, [Sprint 0 구현](#sprint-0-구현)).

### 오류와 진단 상태

- 오류는 단계별로 나눠 보여준다 ([문구 목록](#문구-목록)의 코드별 문구; SCRUM-23, 25). 인증 실패와 실행 실패를 섞지 않는다 (SCRUM-65).
- 에이전트 프로세스가 끝나도 IDE는 계속 돈다. 캐릭터에는 오류 말풍선을, Detail Panel에는 원인과 조치를 보여준다 (SCRUM-22, 47).
- 진단 화면(실행 파일, 설정 경로, 인증, 모델 접근을 나눠 다시 검사)은 post-MVP다 (SCRUM-49, 50). MVP에서는 "연결 확인" 결과가 그 역할을 한다.
- 앱을 닫을 때 실행 중인 에이전트가 있으면 프로세스가 종료된다고 경고한다.

### Sprint 0 구현

데스크톱 렌더러(`webview-ui/src/desktopUi/`)가 위 화면 중 Sprint 0 범위를 그린다. 위 설계에 없던 것과 구현하며 정한 것은 아래와 같고, 모두 제안이다. 문구는 [문구 목록](#문구-목록)의 Sprint 0 표에 있다.

- 배치 (D7): 세 열 [프로젝트·에이전트 패널 | 픽셀 월드 | Detail Panel]이다. 양옆 열은 창 너비를 따라 각각 220–320px, 280–440px 사이에서 바뀌고, 픽셀 월드가 나머지를 쓴다. 창을 900×600으로 줄여도 세 열이 다 보이고, 픽셀 월드의 확대·이동·클릭은 그대로 된다 (SCRUM-22). 창의 최소 크기는 셸이 정한다(800×500). 레이아웃 편집("Layout")과 "+ Agent"는 숨긴다 (D19).
- 프로젝트·에이전트 패널: 프로젝트가 없으면 "프로젝트 없음", "프로젝트 열기", 최근 프로젝트를 보여준다. 최근 프로젝트를 누르면 폴더 선택 없이 그 경로를 연다. 프로젝트가 있으면 이름, 실제 경로, 파일 트리(폴더마다 폴더 먼저, 대소문자 무시 이름순), 에이전트 카드다. 열기 실패는 코드의 문구, 고른 경로, "다른 폴더를 선택하세요"를 보여주고 "프로젝트 열기"로 다시 고른다. 실행 중인 에이전트 때문에 다른 프로젝트를 열지 못하면(`INVALID_STATE`) 그 안내를 쓴다. 프로젝트가 없을 때도 에이전트 칸을 두어, 픽셀 월드·프로젝트 선택 상태·에이전트 패널이 한 화면에 있다 (SCRUM-18).
- 에이전트 카드: 이름, 실행기 배지(어댑터가 마지막으로 보고한 `agentInfo.title`, title이 없으면 `agentInfo.name`이고 세션이 끝나도 그대로 둔다. 보고 전에는 `harnessId`. 이름과 같으면 뺀다, [에이전트 이름 식별](#여러-에이전트-구분)), 설정 상태와 그 안내 한 줄, 에이전트 상태, "에이전트 시작"/"에이전트 종료"/"연결 확인"이다. "에이전트 시작"은 `offline`·`error`이고 설정 상태가 `configured`·`auth_required`일 때만, "에이전트 종료"는 `offline`·`error`가 아닐 때만 켠다. 카드를 누르면 그 에이전트를 선택한다.
- "연결 확인" (SCRUM-25, 49의 최소 형태): 런타임이 `checkConnection`을 받는 `offline`·`error`에서만 켠다. 확인하는 동안 "연결 확인 중"을 쓰고 "에이전트 시작"과 "연결 확인"을 끈다. 끝나면 "연결 확인: <설정 상태> · <오류 문구(단계)> · <인증 표시값>" 한 줄을 보이고, 에이전트를 시작하면 이 줄을 지운다. 설정 상태가 `unsupported`가 된 에이전트(어댑터가 `chat-gpt`를 광고하지 않았다)는 이것으로 다시 확인해야 돌아올 수 있다. 단계별 결과 화면은 에이전트 설정(SCRUM-25)에서 만든다.
- 거절된 명령: 런타임이 명령을 거절하면(`commandRejected`) 그 명령을 보낸 자리에 "요청을 처리하지 못했습니다: <이유>"를 쓴다. 시작·종료·연결 확인은 카드, `sendPrompt`는 작업 입력창, `respondPermission`은 그 권한 요청 칸, `openProject`는 프로젝트 패널이다. 같은 대상에 명령을 다시 보내면 지운다.
- 선택: 캐릭터 클릭과 카드 클릭은 같은 선택을 바꾼다. 프로젝트를 열면 첫 에이전트를 선택한다. 선택한 캐릭터를 다시 누르거나 빈 바닥을 누르면 선택이 풀리고, Detail Panel은 선택을 안내한다. 선택한 캐릭터는 카메라가 따라간다 (상속).
- Detail Panel 순서: 헤더 다음에 지금 사용자가 할 일(시작 단계와 인증 단계 안내, 오류, 대기 중인 권한 요청)을 먼저 두고, 연결 정보(처음에는 접혀 있다), 현재 실행("실행 결과" 포함), 최근 이벤트, Plan, 최종 응답(끝나지 않은 Tool 호출 포함), 컨텍스트 사용량, 작업 입력창 순서다. 위의 1–6 순서를 지키되 작은 창에서도 현재 실행과 답할 요청이 먼저 보이게 하려는 것이다. 할 일이 새로 생기면(시작, 오류, 새 권한 요청) 패널을 맨 위로 올린다. 사용자가 최근 이벤트를 보느라 내려 두었어도 답할 요청을 놓치지 않게 하려는 것이다.
- 현재 실행 칸: "작업 요청"(실행 전에는 "미지정"), "세션 상태", "현재 Tool"("제목 · 행동 · Tool 상태", 끝나지 않은 Tool 호출이 없으면 "상태 정보 없음"), "실행 결과"다. 실행 결과는 진행 중이면 에이전트 상태 라벨("실행 중", "승인 대기", "중지 중")이고, 끝났으면 실행 결과 라벨과 그 색이다([실행 결과 표](#상태-어휘)). 실행 중에 어댑터가 끝났으면 "에이전트 프로세스가 종료됨"이다 (R7). R3, R4 문구도 이 칸에 쓴다. "최종 응답"은 실행이 끝난 뒤에 그 실행의 `agentMessageChunk`를 모두 이어 붙여 보여주고(메시지가 바뀌면 줄을 바꾼다), 끝나지 않은 Tool 호출이 있으면 "미완료" 또는 "취소됨(클라이언트 판단)"을 붙인다. 응답 글은 청크를 받을 때마다 쌓으므로 최근 이벤트의 200개 한도와 상관없이 처음부터 남는다. 다시 연결해 받은 스냅샷의 이벤트 꼬리에 그 실행의 시작(`runStarted`)이 없으면 앞부분이 빠졌을 수 있으므로 "앞부분을 받지 못한 응답입니다"를 붙인다.
- 다시 시작 (R8): 에이전트가 새로 시작하면(`starting`) 이전 실행의 작업 요청, 실행 결과, 최종 응답은 현재 실행 칸에서 뺀다. 그 실행은 이전 세션의 것이고, 최근 이벤트에는 남는다. 다시 시작하기 전(`error`, `offline`)에는 그 실행을 그대로 보여준다.
- 최근 이벤트: 행 하나가 이벤트 하나이고 `seq` 순서다. 같은 메시지(`messageId`, 없으면 같은 실행)의 이어진 청크는 받을 때 한 행으로 합치고, 그렇게 합친 행을 최근 200개까지 둔다 (D24). 생각 청크는 접힌 행이다. 권한 응답 행은 요청 행이 목록에서 빠진 뒤에도 고른 선택지의 kind 라벨을 쓴다. 목록은 높이가 정해진 상자 안에서 스크롤되고, 끝에 있으면 새 행을 따라간다.
- 권한 요청 (D16): 대화상자(SCRUM-33) 전까지는 Detail Panel에 요청마다 칸을 두고, 대화상자의 필드("요청 에이전트", "실제 명령 또는 대상", "작업 디렉터리", "승인 선택지")와 선택지 버튼을 보여준다. 버튼 라벨은 kind로 정하고, 어댑터가 붙인 이름은 버튼에 마우스를 올리면 보인다. 누르면 런타임이 요청을 닫을 때까지 그 요청의 버튼을 끈다. 런타임이 그 답을 거절하면 버튼을 다시 켜고 거절 문구를 쓴다. 캐릭터나 카드를 눌러도 요청과 "..." 말풍선은 그대로다 (R9).
- 작업 입력창: 에이전트가 `ready`일 때만 보낼 수 있다. Enter로 보내고 Shift+Enter로 줄을 바꾼다. 보낸 글은 그 실행이 시작될 때까지 입력창에 남고, 런타임이 거절하면 그대로 남아 다시 보낼 수 있다. "중지"는 런타임이 `cancelRun`을 처리하게 될 때(SCRUM-24) 넣는다.
- 오류: 코드의 문구 아래에 "단계", "원인"(`AgentErrorData.message`, 런타임이 마스킹한 값), "조치"를 한 줄씩 쓴다. 조치는 코드별로 정하고, 정하지 않은 코드에는 다시 시작하라는 문구를 쓴다.
- 이름 라벨: 캐릭터마다 머리 위에 이름, 실행기 배지, 에이전트 상태를 늘 보여준다 (SCRUM-28). 배지는 카드와 같은 규칙으로, 이름과 같으면 뺀다([에이전트 이름 식별](#여러-에이전트-구분)). `offline`이면 흐리게 그린다.
- 렌더러는 런타임이 보낸 값을 그린다. 에이전트 상태, 현재 Tool, 세션 상태, 작업 요청, 응답 글은 스냅샷과 그 뒤에 받은 모든 이벤트로만 정한다. 상태 저장소가 이벤트를 받을 때마다 한 번씩 에이전트의 상태에 반영하므로(`webview-ui/src/runtimeAgentState.ts`), 긴 실행이 200개 넘게 이벤트를 보내도 화면과 캐릭터는 그 실행을 그대로 보여준다. 같은 `toolCallId`의 update가 반복되어도 캐릭터는 하나이고 엔진은 바뀐 것만 고친다 (SCRUM-27).
- 글자 (제안): 패널은 한국어를 단어 사이에서만 줄바꿈한다(`word-break: keep-all`). 경로와 원본 입력은 아무 곳에서나 줄을 바꾼다. 라틴 글자와 한글은 같은 높이로 보이게 크기를 맞춘다([상속한 시각 요소](#상속한-시각-요소)).

## 상태 어휘

상태는 로컬 런타임(Local runtime)이 계산해서 보내고, 렌더러는 받은 값을 그대로 그린다. 전이 조건과 실행 결과를 정하는 규칙은 [ADR 0005](adr/0005-agent-event-model.md)에 있다. 라벨이 Jira 어휘인지는 [문구 목록](#문구-목록)에 있다.

| 에이전트 상태 `AgentStatus` | 라벨      | 뜻                                                                 | 캐릭터 표현                                                                                                                   | Detail Panel                                                                                                                                              |
| --------------------------- | --------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `offline`                   | 꺼짐      | 프로세스가 없다                                                    | 자리에 앉은 채 반투명으로 둔다. 움직이지 않고 말풍선도 없지만, 이름 라벨과 선택은 그대로다. 상속한 반투명 렌더링을 재사용한다 | "에이전트 시작"                                                                                                                                           |
| `starting`                  | 시작 중   | 프로세스 실행부터 `session/new` 성공까지                           | 불투명해지고 자리에서 기다린다                                                                                                | 단계 진행: 어댑터 실행 → ACP 초기화 → 인증 확인 → 세션 생성. 인증 단계(`authenticate`)에서는 "브라우저에서 ChatGPT 로그인을 완료하세요"와 "에이전트 종료" |
| `ready`                     | 대기      | 세션이 열려 있고 진행 중인 실행이 없다                             | 상속한 대기 동작(배회)                                                                                                        | 입력창 활성                                                                                                                                               |
| `running`                   | 실행 중   | 실행(Run)이 진행 중이다                                            | 자리에서 [행동 매핑](#행동-매핑)의 애니메이션. 보고된 Tool 호출이 없으면 범용 작업 표시                                       | "현재 Tool". 보고된 Tool 호출이 없으면 "상태 정보 없음"                                                                                                   |
| `awaiting_permission`       | 승인 대기 | 답하지 않은 권한 요청이 1개 이상 있다                              | "..." 권한 말풍선 (amber, 응답할 때까지 유지)                                                                                 | 대기 중인 권한 요청과 대화상자 다시 열기                                                                                                                  |
| `cancelling`                | 중지 중   | `session/cancel`을 보냈고 `session/prompt` 응답을 기다린다         | 마지막 행동을 멈춘다                                                                                                          | "중지 중"                                                                                                                                                 |
| `error`                     | 오류      | 시작 실패·요청하지 않은 종료·잘못된 ACP 메시지 (프로세스는 끝났다) | 오류 말풍선. 프로세스가 없으므로 자리에 앉은 채 멈춘다 (제안)                                                                 | 원인 코드의 문구와 조치                                                                                                                                   |
| `disconnected` (post-MVP)   | 연결 끊김 | 전송 계층이 끊겼다 (SCRUM-48)                                      | post-MVP에서 정한다                                                                                                           | post-MVP에서 정한다                                                                                                                                       |

| 실행 결과 `RunOutcome` | 라벨      | 캐릭터 표현                                                                       | Detail Panel (글자 색, 제안)                                           |
| ---------------------- | --------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `completed`            | 완료      | 체크 말풍선 (상속, 2초 뒤 사라짐)                                                 | 최종 응답과 "완료" (`--color-status-success`)                          |
| `cancelled`            | 취소됨    | 취소 아이콘 (2초 뒤 사라짐, 제안)                                                 | "취소됨" (흐린 글자색 `--color-text-muted`)                            |
| `refused`              | 거절됨    | 경고 아이콘 (2초 뒤 사라짐, 제안)                                                 | "거절됨" (`--color-warning`)                                           |
| `limit_reached`        | 한도 도달 | 경고 아이콘 (2초 뒤 사라짐, 제안)                                                 | "한도 도달" (`--color-warning`)                                        |
| `failed`               | 실패      | 오류 말풍선 (2초 뒤 사라짐. 에이전트가 `error`가 되면 오류 말풍선이 남는다, 제안) | "실행 실패" 또는 "에이전트 프로세스가 종료됨" (`--color-status-error`) |

"실행 결과" 칸과 최근 이벤트의 "실행 결과" 행은 같은 색을 쓴다. 끝난 실행에는 "승인 대기"의 색(`--color-status-permission`)을 쓰지 않는다. 사용자를 기다리는 것처럼 보이지 않게 하려는 것이다.

실행이 끝났을 때 끝나지 않은 Tool 호출은 결과가 `cancelled`면 "취소됨(클라이언트 판단)", 그 밖이면 "미완료"로 쓴다. 이 판단(`derivedStatus`)과 결과를 정하는 규칙은 [ADR 0005](adr/0005-agent-event-model.md)에 있다.

설정 상태는 에이전트 카드와 Detail Panel 헤더에 표시하고, 캐릭터 표현은 바꾸지 않는다. 설치되지 않은 실행기나 지원하지 않는 조합은 실행할 수 있다고 표시하지 않는다 (SCRUM-26).

| 설정 상태 `Readiness` | 라벨                           | 카드와 Detail Panel                           |
| --------------------- | ------------------------------ | --------------------------------------------- |
| `configured`          | 설정 완료                      | "에이전트 시작" 활성                          |
| `auth_required`       | 인증 필요                      | 어댑터가 제공하는 인증 절차로 안내 (SCRUM-65) |
| `unsupported`         | 지원되지 않음                  | 시작 불가. 원인 표시 (SCRUM-25)               |
| `executable_missing`  | 에이전트 실행기 설치/연결 필요 | 시작 불가. 설치 안내 (SCRUM-36)               |

- `configured`는 정적 설정이 맞고 런타임이 어댑터 실행 명령을 정할 수 있을 때만 온다. 개발 중에는 `npm run adapters:install`로 설치한 codex-acp가 있어야 한다 ([architecture.md](architecture.md#어댑터-실행)). 어댑터가 "로그인 안 됨"을 알리면(연결 확인이나 시작 중에) `auth_required`가 되고, 로그인이 보고되면 `configured`로 돌아간다. `auth_required`인 에이전트도 "에이전트 시작"은 켜 둔다. 시작의 인증 단계가 어댑터의 로그인을 열기 때문이다 (SCRUM-65). 어댑터가 설정한 인증 방식(`chat-gpt`)을 광고하지 않으면(연결 확인이나 시작 중에) `unsupported`가 되고, 광고하는 어댑터를 다시 보면("연결 확인") 돌아간다. 실행 파일이 없어 시작하지 못했으면 `executable_missing`이다. 카드와 "연결 확인" 결과는 늘 같은 값을 보인다.
- Jira 상태어 대응 (SCRUM-6, 11): Running = `running`, Waiting = `ready` 또는 `awaiting_permission`, Completed = `completed`, Failed = `failed` 또는 `error`.
- 상태 색은 상속한 CSS 토큰을 쓴다: 실행 중 `--color-status-active`, 승인 대기 `--color-status-permission`, 완료 `--color-status-success`, 오류·실패 `--color-status-error`. 거절됨·한도 도달은 `--color-warning`, 취소됨은 흐린 글자색이다 (제안).

"세션 상태"는 Detail Panel의 현재 실행 칸에만 쓴다. ACP 세션의 상태이고 에이전트 상태와는 따로다. 런타임이 보낸 값으로만 정한다: 열린 세션은 `sessionStarted`(스냅샷의 `sessionId`), 끝난 세션은 `sessionEnded`(스냅샷의 `sessionEnd`)의 `reason`이다 ([ADR 0005](adr/0005-agent-event-model.md)). 라벨은 모두 제안이다 (D23).

| 세션 상태                | 조건                                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------- |
| 세션 없음                | 세션을 연 적이 없거나, 새로 시작하는 중이다(`starting`). 시작 단계에서 실패해 세션이 없었을 때도 같다 |
| 세션 열림                | `sessionStarted` 뒤, `sessionEnded` 전                                                                |
| 세션 종료됨(중지)        | `sessionEnded {reason: stopped}`: "에이전트 종료"로 끝냈다                                            |
| 세션 종료됨(비정상 종료) | `sessionEnded {reason: exited}`: 어댑터 프로세스가 스스로 끝났다                                      |
| 세션 종료됨(중단)        | `sessionEnded {reason: aborted}`: 잘못된 ACP 메시지 때문에 런타임이 끊었다                            |

다시 시작하면 새 세션이다. 이전 세션을 이어간다고 표시하지 않는다 (R8).

## 행동 매핑

| 행동 (Jira)  | ACP `ToolKind`                               | 캐릭터                             | 아이콘                      |
| ------------ | -------------------------------------------- | ---------------------------------- | --------------------------- |
| 검색 Search  | `search`                                     | 읽기 애니메이션                    | 돋보기                      |
| 읽기 Read    | `read`, `fetch`                              | 읽기 애니메이션                    | 없음                        |
| 편집 Edit    | `edit`, `delete`, `move`                     | 타이핑 애니메이션                  | 없음                        |
| 실행 Execute | `execute`                                    | 타이핑 애니메이션                  | 터미널 아이콘               |
| 기타 Other   | `think`, `switch_mode`, `other`, `kind` 없음 | 범용 작업 표시 (타이핑 애니메이션) | 톱니 (범용 작업 표시, 제안) |

- 캐릭터는 가장 최근에 시작했고 아직 끝나지 않은 Tool 호출의 행동을 보여준다.
- 알 수 없는 kind에는 범용 작업 표시를 쓰고, `kind`가 없으면 Detail Panel에 "미지정"으로 쓴다 (R6). 보고되지 않은 활동은 그리지 않는다. 같은 `toolCallId`의 update가 반복되어도 캐릭터를 새로 만들거나 애니메이션을 다시 시작하지 않는다 (SCRUM-27). Tool 호출의 전역 키는 [architecture.md#식별자](architecture.md#식별자)에 있다.
- 구현 메모: 상속한 엔진은 `readingTools` 목록에 있는 Tool이면 읽기, 아니면 타이핑을 고른다. 데스크톱 렌더러는 이 목록을 `read`, `search`, `fetch`로 두고 ACP `kind`를 엔진의 Tool 이름으로 넘긴다. 범용 작업 표시는 타이핑 애니메이션에 톱니 아이콘을 더한 것이다. 아이콘은 말풍선과 같은 자리에 그리고, 말풍선이 있으면 말풍선이 앞선다. 보고된 Tool 호출이 끝났는데 실행이 이어지면(답 청크만 올 때) 범용 작업 표시다 (제안).

## 관찰한 것만 보여준다

모든 화면에 적용한다. 고정 문구는 문구 목록의 글자를 그대로 쓴다.

- **R1** 표시하는 활동은 ACP에서 확인한 것뿐이다 (SCRUM-19, 21, 23).
- **R2** Plan은 어댑터가 `plan`을 보낼 때만 보여주고, 계획을 지어내지 않는다 (SCRUM-19). 우선순위는 표시하지 않는다. codex-acp가 `medium`으로 고정해서 보내기 때문이다 (2026-10-20 기준).
- **R3** 실행기 카탈로그가 Tool 상세를 보내지 않는다고 적은 실행기(`AgentSummary.reportsToolDetails: false`)에만 "이 실행기는 세부 활동을 제공하지 않습니다"를 쓴다 (SCRUM-19). 실행을 관찰해서 판단하지 않는다. 아직 이벤트가 오지 않았을 뿐이면 R5를 따른다.
- **R4** 서브에이전트(Sub-agent) 캐릭터는 post-MVP다 (SCRUM-56). 그때도 ACP가 검증된 부모·자식 세션 ID를 보고할 때만 만든다 (SCRUM-21). MVP에서는 Agent나 Task Tool 호출을 일반 Tool 호출로 보여준다. 카탈로그가 자식 세션을 보고하지 않는다고 적은 실행기(`reportsSubagentSessions: false`)는 Detail Panel에 늘 "하위 Agent 정보 미제공"과 "일부 활동만 관찰 가능"을 쓴다. Tool 제목으로 하위 Agent를 추측하지 않는다 (SCRUM-21, 66). 규칙은 [ADR 0005](adr/0005-agent-event-model.md) 결정 10에 있다.
- **R5** 이벤트가 없으면 행동을 지어내지 않고 "상태 정보 없음"을 쓴다 (SCRUM-27).
- **R6** kind나 status가 없으면 "미지정"으로 쓴다. 기본값을 사실처럼 보여주지 않는다 (SCRUM-19).
- **R7** 실행 중에 프로세스가 끝나면 절대 "완료"로 표시하지 않는다 (SCRUM-23, 47).
- **R8** 다시 시작한 뒤 이전 실행을 "실행 중"으로 보여주지 않는다. 이전 세션을 이어간다고 표시하지 않는다 (SCRUM-32, 37, 47, 48).
- **R9** 권한 요청을 허용하는 것은 사용자가 고른 선택지뿐이다. 닫거나 정보가 불분명해도 허용하지 않는다 (SCRUM-33).
- **R10** 보호 수준은 "작업 폴더 설정"과 "실제 OS/Harness 강제 제한 여부"로 나눠 보여준다. agents-room은 OS 격리를 하지 않으므로 OS 제한은 "없음"이다. 실행기의 제한은 어댑터가 보고한 mode가 있을 때만 그 값으로 보여주고, 없으면 "실제 제한 여부 확인 불가"를 쓴다. 보호되는 것처럼 표시하지 않는다 (SCRUM-35, 62).
- **R11** 인증 정보는 [ADR 0004](adr/0004-model-authentication.md)가 허용한 것만 표시한다. 요금제와 모델은 어댑터가 보고한 값만 쓴다 (SCRUM-34, 65).
- **R12** 컨텍스트 사용량은 `usage`(`used`/`size`)가 보고될 때만, 비용은 `cost`가 있을 때만 보여준다 (예: "52000 / 200000 (26%) · 비용 0.12 USD", 금액과 통화는 받은 그대로). 검사할 수 없는 항목은 "검사 불가"로 표시하고 정상으로 보지 않는다 (SCRUM-49).

## 여러 에이전트 구분

- 에이전트마다 고유한 팔레트를 쓰고, 이름 라벨을 늘 보여준다. 실행기 배지는 아래 규칙대로 붙인다 (SCRUM-28). 팔레트는 상속한 방식대로 런타임이 배정한다: 6종을 먼저 쓰고, 그다음에는 색조를 45–315° 옮긴다. 서브에이전트 캐릭터(R4)는 상속한 동작대로 부모와 같은 팔레트로 부모 근처에 둔다.
- 에이전트 이름 식별 (제안): 이름 라벨, 에이전트 카드, Detail Panel 헤더는 이름과 실행기 배지를 한 규칙으로 쓴다 (SCRUM-27). 이름이 배지 글자(어댑터가 마지막으로 보고한 `agentInfo.title`, title이 없으면 `agentInfo.name`, 보고 전에는 `harnessId`)와 같으면 이름만 한 번 쓴다. 비교는 앞뒤 공백을 빼고 대소문자를 무시한다. 그래서 Codex 실행기의 "Codex" 에이전트는 "Codex Codex"가 아니라 "Codex"로 보이고, 카드와 Detail Panel 헤더에서 이름에 마우스를 올리면 "실행기: Codex"가 보인다. 이름이 다르면("Gemini"와 `gemini-cli`, "Codex 2"와 "Codex") 이름 옆에 배지를 그대로 둔다. 이름은 저장된 그대로 쓴다. 규칙은 `webview-ui/src/desktopUi/agentControls.ts`의 `agentIdentity` 한 곳에 있다.
- Detail Panel, 권한 대화상자, 입력창은 모두 `agentId`에 묶인다 ([architecture.md#식별자](architecture.md#식별자)). 한 캐릭터의 상태가 바뀌어도 다른 캐릭터의 애니메이션을 방해하지 않는다. 이벤트가 몰리면 화면 갱신을 묶되 주요 상태 전이는 빠뜨리지 않는다 (SCRUM-28, 66).

## 상속한 시각 요소

- 스타일 토큰 (`webview-ui/src/index.css`): `--color-bg`(`#1e1e2e`), `--color-bg-dark`, `--color-border`, `--color-accent`, `--shadow-pixel`(`2px 2px 0px #0a0a14`), `--font-pixel`(`'FS Pixel Sans'`와 한글 대체 글꼴), 상태 토큰 4개. 모서리는 각지게(`border-radius: 0`), 테두리는 2px 실선으로 그린다.
- 한글: FS Pixel Sans에는 한글 글리프가 없다. 그래서 `--font-pixel`은 FS Pixel Sans 다음에 시스템 한글 글꼴(`Malgun Gothic`, `Apple SD Gothic Neo`, `Noto Sans KR`)을 둔다. 라틴 문자는 픽셀 글꼴로, 한글은 시스템 글꼴로 보인다. 같은 글자 크기에서 FS Pixel Sans의 대문자는 0.44em, 맑은 고딕의 한글은 0.85em 높이라 라틴 글자가 한글의 절반 높이로 보인다. 그래서 데스크톱 패널(`.desktop-type`)은 크기를 맞춘 한 쌍을 쓴다: 같은 픽셀 글꼴을 140%로, 한글 글꼴을 85%로 그려(`@font-face`의 `size-adjust`) 한글이 라틴 대문자보다 조금 높게, 한글 글꼴이 자기 라틴 글자와 그리는 비율에 가깝게 보인다. VS Code와 standalone은 그대로다. 한글 픽셀 글꼴(라이선스와 글리프 범위 확인 필요)은 나중에 정한다. 데스크톱 렌더러는 문서 언어를 `ko`로 둔다 (제안).
- ESLint 규칙 (`eslint-rules/pixel-agents-rules.mjs`, 모두 error 수준): `no-inline-colors`(색 리터럴은 `constants.ts`와 스프라이트 데이터에만), `pixel-shadow`(`2px 2px 0px` 하드 오프셋 그림자), `pixel-font`(FS Pixel Sans). CLAUDE.md와 ESLint 메시지가 쓰는 `--pixel-*` 토큰 이름은 실제 이름과 다르다 → [upstream.md#알려진-불일치](upstream.md#알려진-불일치).
- 캐릭터: 6종 시트(`char_0`–`char_5`, 프레임 16×32), 4방향(왼쪽은 오른쪽을 뒤집는다), 걷기·타이핑·읽기 프레임, 생성·소멸 때 matrix 효과(0.3초), 정수 배율 확대. 선택하면 카메라가 따라간다.
- 말풍선: 권한 "...", 대기 체크(2초). 알림음은 선택 기능이다 (Settings). Sprint 0에서 오류 말풍선(빨간 "!"), 취소 아이콘(회색 "X"), 경고 아이콘(주황 삼각형), 돋보기, 터미널 아이콘(">_"), 범용 작업 표시(톱니)를 상속한 말풍선과 같은 11×13 틀로 새로 그렸다 (`webview-ui/src/office/sprites/`의 JSON, 직접 그렸으므로 제3자 고지가 필요 없다).
- 레이아웃은 기본 사무실을 쓴다. 레이아웃 편집기(SCRUM-59)와 테마(SCRUM-60)는 post-MVP다.
- 펫, 카펫, 인트로 투어는 상속한 그대로 유지한다 (2026-10-23 팀 결정). 펫은 장식이며 에이전트 상태를 나타내지 않는다. 인트로 투어는 hooks 동의 단계를 빼고 온보딩(프로젝트 열기, 에이전트 추가, Codex 로그인 안내)으로 바꾼다 ([upstream.md](upstream.md#상속-범위)). 아직 바꾸지 않았고, 지금의 투어는 hooks 동의 요청으로만 열리므로 데스크톱에서는 열리지 않는다. Areas는 정하지 않았으므로 MVP 범위에 넣지 않는다.
- 상속 범위는 [upstream.md#상속-범위](upstream.md#상속-범위), 크레딧(캐릭터 JIK-A-4, 폰트 NZWStudios2024)은 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)에 있다.
